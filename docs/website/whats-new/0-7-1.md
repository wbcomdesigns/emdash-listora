# 0.7.1

**Included in Free**

Released as `@vapvarun.bsky.social/listora@0.7.1`. GitHub tag `v0.7.1`. Copy the kit again after you update, with the new tag, as the [install guide](../getting-started/install.md) shows. Fixes from the first walk of 0.7.0 on a Cloudflare site.

- **The upgrade starts by itself.** After an update from 0.6.x, the first visitor to the directory starts the data upgrade within about a minute. No admin needs to open a Listora page first.
- **Import goes on where it stopped.** A spreadsheet goes to the site two rows at a time. When the site is slow to answer, the import page waits and tries again; if it still cannot finish, it says how many rows were added and which row it stopped at, and Continue carries on from there. A row is never added twice, even when the site created it just before it stopped answering.
- **Plain words for a request the site could not finish.** The kit no longer shows the server's own technical text.
- **Expiry from the Plugins settings form.** Turning on listing expiry in the plugin's settings form under Plugins (not only on Listora, Settings) now expires listings on the daily schedule. The days are limited to 0 to 3650 and photos per listing to 0 to 20 there too.
- **A site that cannot send email.** With email notices on and no email provider, Messages says so in a banner and on each message ("Not notified: this site cannot send email"). The notices go out once a provider is set up under Settings, Email.
- **Small fixes.** After Send changes for approval, the edit page says the changes are waiting. Listing reviews counts owner replies waiting for approval next to the reviews waiting.
- **For developers.** The kit reaches the plugin through the shared Wbcom helper `src/lib/wbcom-kit.ts`; the setup script copies it only when the site has none or an older one. Delete my data erases only on a POST request. Every publish reads the listing's current revision first, as EmDash's docs require. The plugin needs EmDash 1.2.0 or later.
