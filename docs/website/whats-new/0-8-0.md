# 0.8.0

**Included in Free**

Released as `@vapvarun.bsky.social/listora@0.8.0`. GitHub tag `v0.8.0`. Copy the kit again after you update, with the new tag, as the [install guide](../getting-started/install.md) shows. No new permissions.

## After you update

For a short time after the update, forms on the site say it is **finishing an update** while EmDash builds Listora's new storage indexes. Wait a minute and try again. Then the data catches up by itself in the background: each listing gets its category rows, city copy, chip and sort values, a hundred listings at a time, so a large directory is fully up to date within hours (about four hours for 6,000 listings with categories). Nobody needs to open an admin page for it. Until a listing is caught up, it can be missing from a category, chip or sort filter.

## What is new

- **Listing types you can edit.** Listora, [Listing types](../features/listing-types.md) lists every type. Add your own, and rename, recolour, change the icon of or hide a built-in one. Your own types can be deleted while no listing uses them.
- **Custom fields.** Each type has its own fields: text, number, choice from a list, link, date, or yes or no. They show on the submit and edit forms, in a **Details** section on the listing page, on directory cards when you mark them for cards, and as columns in CSV import and export. See [Add a listing](../features/submit.md).
- **Types without a place.** Turn off "Listings have a place" on a type and its listings have no map, address, city, opening hours, directions, Open or Closed, or location search, on every screen.
- **Software type.** One built-in type for plugins, skills, agents, MCP servers, apps, libraries and themes, with badges, an **Install** box with **Copy**, live GitHub stars in the visitor's browser, and `SoftwareApplication` data for search engines. See [Software](../features/listing-types.md#software).
- **Filter chips.** One choice field per type can be its chip field. Pick the type in the directory and its chips appear: for Software, **What it is** (Plugin, Skill, Agent and the rest).
- **Sort by a type's own fields.** Up to three number or date fields per type can be sorts. Pick a type in the directory and they join Featured, Rating and Title.
- **Managed by its author.** A listing a member added shows **Managed by its author**. **Claimed listing** stays for listings an approved claim moved to their owner.
- **Sample directory page.** Get started, **Load sample directory** opens the kit page `/listings/sample/`, which adds 17 listings (14 New York places and 3 Software listings) with reviews and a claim. Two of them wait for your approval.

## Improvements and fixes

- The directory pages through Listora's index, so filters and sorts work on any number of listings, and a listing filed under several categories is found under each.
- Keyword search uses EmDash's own site search, best match first.
- The **Calendar** button shows only with no type or Event picked, and the calendar lists events added since 0.8.0.
- Loading the sample directory again on a site with many listings no longer adds them twice.
- CSV import stores no address for a type without a place.
- Small fixes from the 0.7.0 walk: fresher waiting counts in admin buttons, easier tap targets on a phone, clearer title and rate-limit messages.

## For developers

- A guide to [syncing listings from an outside source](../developer-guide/outside-sync.md) through the content API.
- Storage indexes match every filtered and sorted query; unused ones were removed. The `listings` route takes `category`, `city_exact`, `chip` and slot sorts (`n1` to `n3`, only with a `type`). See [Plugin routes](../developer-guide/routes.md).
- Needs EmDash 1.2.0 or later; tested on EmDash 1.5.0.
